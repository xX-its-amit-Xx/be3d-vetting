BE3D — every use, every user,
every rival.

BE3D (beclust3d v1.0.0, Broad Institute) turns a completed base-editor tiling-mutagenesis screen into 3D structural hotspots of functionally important residues — mapping per-residue log-fold-change onto an AlphaFold/PDB structure, smoothing it in space (LFC3D), testing it against a randomization null, and clustering the survivors into hotspots.

This dossier vets it exhaustively: the competitive field, 20 user personas across academia & industry, a persona×use-case fit matrix, market impact, cross-domain analogies, a code-level design deep-dive, a real run on the KBTBD4 example, and an adoption path via LLM/MCP.

The bottom line

A real, narrow, defensible niche — with one serious rival

BE3D occupies a genuine gap: the only openly-packaged, base-editing-native, control-aware, meta-aggregating pipeline that converts a functional tiling screen into statistically-tested 3D structural hotspots and hands them to an interactive portal.

Its novelty is real against the two worlds it bridges — it is not competing with upstream screen callers (MAGeCK, BAGEL, BEAN) or variant predictors (AlphaMissense, ESM); it consumes their output and adds a 3D layer none of them have. Against the cancer-genomics 3D-hotspot lineage (HotMAPS, HotSpot3D, CLUMPS) its deep differentiator is the signal type: a designed, continuous readout with real negative controls, not somatic mutation recurrence.

The one question that matters: BE3D vs ProTiler-Mut

A concurrent tool — ProTiler-Mut (He et al., Cell Systems 2026) — does the same high-level thing: map CRISPR tiling-mutagenesis screens to 3D and call hotspot substructures.

BE3D edges
  • Base-editing-native mutation parsing
  • Randomization null using the screen's own controls
  • Cross-species / isoform meta-aggregation
  • Direct G2P interactive-portal export
ProTiler-Mut edges
  • Rank-based (3D-RRA) robustness
  • Multi-condition phenotype modeling
  • Lineage/brand of established ProTiler
  • Explicit PPI-disruption emphasis

Verdict: differentiated enough to coexist. BE3D should win on base-editing specificity + portal integration; it must publish a head-to-head benchmark to hold the ground.

The mechanism

Three modules, one idea: denoise in 3D

The core insight: single-residue screen signal is noisy, so aggregating over 3D spatial neighborhoods surfaces structurally-coherent functional hotspots that a 1D, sequence-order view misses — allosteric sites, interfaces, folding cores.

A · BE-QA

Quality gate

Mann-Whitney U + Kolmogorov-Smirnov tests: do knockout guides (nonsense/splice) separate from neutral guides (silent/no-mutation)? Two hypotheses; failing screens are dropped before interpretation.

→
B · BE-Clust3D

LFC3D + hotspots

Map LFC per residue onto the structure → LFC3D = mean of a residue's LFC and its neighbors within 6Å → randomization null → z-score / p-value by direction → agglomerative clustering into hotspots → characterize (RSA, pLDDT, domains).

→
C · BE-MetaClust3D

Consensus

Aggregate LFC3D across many screens (SUM) to rescue weak-but-concordant signal; an optional MUSCLE/Clustal alignment step integrates cross-species / cross-isoform screens.

→
Out

G2P export

A Genomics 2 Proteins-formatted TSV drives interactive 3D viewing of hits & clusters on the structure.

Inputs: a screen-scores TSV (Mutation_type, Mutation_list, Gene, sgRNA_score) + a UniProt ID (auto-fetches the AlphaFold model, isoform-aware) or a custom FASTA+PDB. Run zero-install in Colab, or locally from a YAML config.

Decision guide

Should you reach for BE3D?

Use BE3D when…

  • You ran a base-editor tiling screen and have per-guide LFC
  • You want 3D hotspots, not a 1D hit list
  • You have multiple screens (editors / conditions / species) to consolidate
  • Your target has an AlphaFold or PDB structure
  • You want interactive figures via G2P

Pair it with…

  • MAGeCK / BEAN upstream to compute clean LFC
  • PyMOL / ChimeraX for offline figure polish
  • AlphaMissense / ESM to cross-check hotspots vs predicted pathogenicity
  • cBioPortal / ClinVar to ask if a hotspot recurs in patients
  • An LLM to author the YAML & interpret hits

Look elsewhere when…

  • You need pre-experiment prediction → BE-Hive, AlphaMissense
  • Your data is somatic mutation frequency → HotMAPS, Oncodrive3D
  • You only need gene-level hit calling → MAGeCK, BAGEL
  • Your assay is DMS not base editing (fit degrades)
  • You need a validated GxP pipeline with SLA today
Cross-domain analogies

BE3D's algorithm is a re-derivation of mature methods elsewhere

Abstractly: noisy point measurements along a sequence → project to a 3D point cloud → neighborhood-smooth → permutation null → spatial clustering → multi-experiment consensus. That pattern is solved — often more rigorously — in six other fields. Each card names the mature technique and the concrete upgrade BE3D could borrow.

Critique · balanced

What it nails, what it risks, where to double down

Strengths

  • Right idea, real niche — 3D spatial aggregation is exactly how adjacent fields attack this signal shape.
  • Honest QC gate — non-optional MWU+KS on knockout-vs-neutral before any interpretation.
  • Has a null — seeded randomization baseline, z-normalized; better than eyeballed thresholds.
  • Bidirectional — splits +/− effects (LOF vs GOF/resistance) instead of |LFC|.
  • Meta-aggregation — the correct lever to rescue weak signal across noisy screens.
  • Interoperable & low-friction — UniProt/AlphaFold auto-fetch, Colab, MIT, G2P handoff.

Weaknesses / risks

  • Twin hard 6Å cutoffs (smoothing + clustering) — scale-blind, discontinuous, no data-driven radius.
  • No FDR / q-values across residues — a real multiplicity gap at proteome scale.
  • Clusters get no significance — geometric single-linkage only; no cluster-level p-value; chaining risk.
  • Global null ignores local mutation tolerance & guide-count heterogeneity.
  • Naive SUM meta — ignores per-screen reliability & between-screen heterogeneity.
  • pLDDT not propagated into stats — low-confidence hotspots can be geometry artifacts.
  • Fragile toolchain (DSSP fails on large PDBs; MUSCLE/Clustal broken on ARM) & no tests/CI/CLI.

Where to double down — a prioritized roadmap

Distance-decay (Gaussian) kernel with a data-driven length scale

Replace the hard 6Å cutoff; fit the scale from a semivariogram/correlogram (kriging / Getis-Ord Gi*). Highest-impact, well-precedented.

Cluster-level permutation p-values + FDR/q-values

Adopt cluster-mass permutation (Maris-Oostenveld) at residue & cluster level; report Benjamini-Hochberg/Storey q.

Local / covariate-adjusted null

MACS-style local λ; adjust the null for pLDDT, RSA, and guide count so quiet cores and noisy loops are judged fairly.

Inverse-variance / empirical-Bayes meta + I² heterogeneity

Weight screens by BE-QA quality; surface when screens disagree instead of silently summing.

Uncertainty & robustness

Per-residue confidence intervals; sigma-clipped/median aggregation; deblending & non-single-linkage clustering.

Engineering hardening

A real CLI (be3d run config.yaml), JSON results manifest, unit tests + CI, seeded-by-default, and a bundled DSSP fallback to kill the mkdssp failure.

Design deep-dive · from the source

How the repository is actually built

Architecture

A per-stage pipeline over four subpackages, writing TSV/gzip artifacts into workdir subdirs so runs are resumable and auditable.

qa/
screen quality gate (MWU + KS)
lfc3d/
the core — structure, conservation, preprocess, randomize, prioritize, calculate_lfc3d, clustering, characterization
aggregate/
per-screen (nonaggregate) & across-screen (metaaggregate) scoring
helpers/
G2P export; a vendored MUSCLE binary (macOS-arm64 only)

No package-level CLI: all orchestration lives in a 1,608-line examples/be3d_local.py with four run modes (monomer, complex, ppi_diff, blind_target).

Algorithm internals

  • LFC3D(i) = tunable aggregation (default mean) of residue i's LFC ∪ all neighbors ≤6Å (CA–CA, or min heavy-atom distance at atom level via a KD-tree). Neighbor topology precomputed once per screen.
  • Null = permute per-guide LFCs (np.random.permutation, seeded, nRandom=1000) → re-aggregate to residues → re-smooth in 3D.
  • Significance is one-tailed by direction: LFC z-scored vs No-Mutation control μ/σ; LFC3D vs the randomization-null μ/σ; thresholded p<.05/.01/.001.
  • Clustering = sklearn Agglomerative, single-linkage, euclidean on CA coords of significant residues, swept 4→20Å.
  • Meta = per-residue SUM of LFC3D across screens (neg & pos aggregated independently).

Engineering — strengths

  • Clean modular decomposition; full NumPy-style docstrings; flat public API.
  • Seeded, reproducible null; per-iteration default_rng(i).
  • Defensive assert input contracts; hot-path reuse of neighbor sources across 1,000 randomizations.
  • Graceful fallbacks: pure-Python PDB parser, remote MUSCLE API, user-supplied FASTA/PDB/DSSP/alignment.

Engineering — smells

  • No tests, no CI for a statistical method — the single biggest gap.
  • warnings.filterwarnings('ignore') at import in many modules — hides real signals.
  • '-' string sentinels mixed into float columns → object dtypes & coercion round-trips.
  • Hard unipos == PDB residue_number assumption; mismatched user PDBs silently drop residues.
  • hatchling/setuptools packaging mismatch; live UniProt/AlphaFold/EBI deps via unmaintained wget.

This tool is from the Iqbal Lab (PI Sumaiya Iqbal), Broad Institute, in collaboration with the Liau Lab (Brian Liau, Harvard) — not an "APAR lab" (that string appears only inside base64 image blobs in a notebook). Use-case deep dive · real output

Case study: KBTBD4 — a molecular-glue degron, in 3D

We installed BE3D and ran its shipped example: the Yeo et al. ABE + CBE tiling screens of KBTBD4 mapped onto the 8VOJ cryo-EM structure of the CRL3KBTBD4–HDAC1 complex (chain B, UniProt Q9NVX7-2). KBTBD4 is a CUL3 substrate receptor whose Kelch β-propeller is reshaped by the molecular glue UM171 to license degradation of HDAC1/2 — a textbook structure-function question where 3D hotspots should light up the glue/substrate-binding surface.

The decisions a scientist actually makes

  • QA gate — accept the screen? BE3D uses Hypothesis-2 KS p<0.05 (knockout vs pooled neutral).
  • Radius — 6Å is the default for both smoothing & clustering; larger merges patches, smaller fragments them.
  • Aggregation — mean (denoise) vs sum (accumulate) for LFC3D; mean vs SUM across the ABE+CBE meta step.
  • Residue vs atom level — CA–CA is fast; min heavy-atom captures side-chain contacts at the interface.
  • p-threshold — 0.05 / 0.01 / 0.001 trade sensitivity for specificity; which to cluster on?
  • Direction — negative (dropout/LOF) vs positive (enrichment) hotspots read as different biology.
  • Chain / PPI scope — score KBTBD4 alone, or include HDAC1 cross-chain neighbors for interface hotspots?
  • Structure choice — the experimental 8VOJ complex vs the AlphaFold monomer changes the neighborhood graph.
BE3D applied to real problems · not reproducing papers

Three new questions, answered on public data

We put BE3D to work on three real, public base-editing screens it had never seen (none are its shipped examples), each on a genuinely open 3D question the source paper did not answer. Every target got an exhaustive parameter sweep (radius 4/6/8/10 Å, mean vs sum, nRandom 500/1000, residue vs atom, monomer vs PPI) with a full decision log; only findings robust across the sweep are reported. As a sanity check, BE3D independently re-discovered known resistance/clinical residues in each case — then surfaced something new.

KRAS · drug resistance

Two G12C drugs, two different 3D escape maps

Data: Coelho/Dincer 2024 (Nat Genet), ~3,000 KRAS guides, sotorasib & adagrasib arms, mapped on 6OIM/6UT0 + AlphaFold. 18 runs, all exit 0.

Open gap: the paper never spatially clustered resistance. Do the two inhibitors escape via the same residues?

  • No. Sotorasib & adagrasib share only 5 residues (Jaccard ≈ 0.12).
  • Adagrasib = one 27-residue orthosteric shell (60–72, 89–103).
  • Sotorasib = sparse pocket + a physically separate distal cluster.
  • ✓ control: re-finds known Y96 / R68 / H95 / Q99 (H95/Q99 adagrasib-specific, as published).

NEW: a robust sotorasib-specific distal α5 cluster (147–156, ~27 Å from the drug); residues 148/154 significant in 7/7 AF runs. No prior report names this as a resistance site — a candidate allosteric-latch locus (flagged as hypothesis).

Act: a sotorasib-class binder reaching toward the His95 groove should raise the resistance barrier; test α5 147–156 mutants for sotorasib-selective IC50 shift (Boltz pre-screen).

MCL1 · apoptosis (PPI mode)

Dependency and drug both live on the BH3 groove

Data: Hanna 2021 (Cell), MCL1 CBE tiling (dropout + BH3-mimetic arms), on 3PK1/3MK8/6QB4 + AlphaFold. 19 monomer + 2 complex runs.

Open gap: is the essentiality hotspot the BH3-groove PPI interface or the drug pocket?

  • Both dependency & S63845-resistance enrich on the same BH3 groove (Fisher OR=∞, p≈5–8e-4), not the pocket-only residues.
  • → functional-genomics evidence that S63845 is a true orthosteric mimetic.
  • Robust groove hotspots R215/V216/V220/T254/N255/V256/F258/T266/F270; strongest T212I (+2.44).

NEW: a second, off-groove resistance compartment (α2 R176/Q177/S178/E180; C-term E325/G326; N-terminal PEST/phosphodegron E85/R78/P80/R95) — all >8 Å from drug = escape via MCL1 stability, not drug binding.

Act: orthosteric mimetics must de-risk the 9 groove escape residues; MCL1 degraders should target the stability axis to bypass groove escape.

DNMT3A · epigenetics / AML

A base-editable proxy for the R882 hotspot

Data: Lue/Liau 2023 (Nat Chem Biol), DNMT3A base-editor scanning — an activity-reporter assay (citrine), on 4U7T. 12 runs, QA pass.

Open gap: which specific interface on the complex carries the loss-of-function vulnerability?

  • Dominant protein interface = the RD homotetramer interface (enrich 1.5–2.4×, 8/12 runs); FF interface second.
  • Robust patch T671/M674/V675/R676/H873/D876/V877/S878 (p<.001 in 12/12).
  • ✓ control: FF hotspots R729/R736 co-localize with clinical residues (R736H = 2nd-commonest DNMT3A mutation).

NEW: the dominant clinical hotspot R882 is base-editing-invisible (CBE can't make R882H) — yet BE3D flags the same tetramerization interface through a clinically-unannotated, base-editable patch, a testable proxy for the R882 defect and a candidate tetramer-disruption drug epitope.

Act: epigenetics/AML groups validate the T671/873–878 patch as an R882 proxy and druggable interface.

These are BE3D-generated, structure-grounded hypotheses from public screen data — strengthened by the recovery of known residues as positive controls, and bounded by the caveats in each decision log (enrichment-vs-dropout direction, AlphaFold confidence in the KRAS α5/HVR region, per-guide causality). Full decision logs, parameter sweeps, honest discrimination benchmarks, and outputs are in the repo: research/P2_run_*.md & P2_user_*.md — see the Validation section for the benchmarked verdicts.

Honest validation · does it discriminate, or call everything?

Benchmarked against ground truth — with the failures shown

Recovering a known hotspot proves nothing if a tool flags a third of the protein. So for each user package we test discrimination, not recall: the base rate (how much it flags at all), enrichment vs chance (hypergeometric/Fisher), the functional-vs-tolerant gap, and — critically — whether BE3D beats a trivial baseline (just calling buried residues, or AlphaMissense). The verdicts below are deliberately uneven. Each links to the full, reproducible benchmark.

Consistent finding across targets: BE3D's base rate swings from ~13% (KRAS) to 37–45% (TP53/MCL1/DNMT3A) — so its raw p<0.05 flag can't be trusted uniformly; you must rank. That's the concrete cost of its missing FDR/q-values.

Where BE3D genuinely adds signal

  • Druggable but not point-mutated targets — MCL1 is amplification-driven, so somatic 3D-hotspot tools (3dhotspots.org) return nothing; a functional screen is the only 3D map.
  • Drug-escape geometry — KRAS adagrasib resistance (8/9 known residues, 5.6× chance): recurrence tools only see the activating G12/G13/Q61 codons, an orthogonal axis.
  • Effect direction & editor-accessible proxies — LOF vs GOF, and interface patches (DNMT3A) that stand in for base-edit-inaccessible clinical sites.

Where it doesn't (shown, not hidden)

  • AlphaMissense out-discriminates it on conserved cores — on TP53, AM ranks the DNA-binding core better (OR 55 vs 33).
  • It can't beat "is it folded?" — on BRCA1 the domain signal is fully recapitulated by a pLDDT>70 baseline; residue-level agreement with Findlay SGE is ~0 (ρ≈0.05) with real false positives.
  • Unproven ≠ absent — KRAS sotorasib shows no significant pocket enrichment; that finding is labeled a hypothesis, not a win.
  • Blind spots — base editing can't reach some validated residues at all (DNMT3A R882; ~half of MCL1's functional set) → false negatives, complementary to predictors.

What real use surfaced · a fix list for BE3D

Using it hard is the best critique

Running BE3D end-to-end on four unfamiliar targets (Windows / Python 3.14 / pandas 3.x) exposed concrete, fixable gaps — logged live in BE3D_IMPROVEMENTS.md. Several are one-line fixes that would materially widen who can run the tool.

Blockers (fix first)

  • DSSP hard dependency — a missing mkdssp aborts the whole run, though DSSP only feeds the final characterization step. Wrap it / ship a pure-Python fallback.
  • Hardcoded "No Mutation" control name — screens whose controls are tokened UTR/Intron crash at prioritize_by_sequence. Let the config name the control category.
  • PPI complex mode can't take a structural-only partner — a bound peptide/ligand that isn't itself tiled crashes; that's the common interface case. Allow a data-less partner as a pure structural neighbor.
  • Windows blockers — pandas-3.x positional to_csv sep; p<0.05 in filenames; deep ppi_partners/ path > MAX_PATH. All one-line fixes.

Correctness & the sharpest science gap

  • Dropout sign is baked in. BE3D assumes LOF = negative score. On an activity-reporter or resistance-enrichment screen that's inverted — and QA still "passes" (MWU/KS are direction-agnostic), so the biology can flip silently. Add an explicit assay_direction / invert_score flag and make QA test the correct tail.
  • Complex mode on a co-crystal ≠ interface-aware. With a data-less partner it's numerically identical to monomer (cross-chain values are empty) — easy to over-assume. Document it; add an optional cross-chain contact annotation in monomer mode.
  • Silent edit drops. Engineered crystal constructs (mutations + non-canonical numbering) fail the refAA match and get dropped with only a buried print. Emit an "N edits unmapped" summary.
  • "Turnkey" ≠ trusted schema. A published supplement's real columns drifted from every recipe — verify the column map against a live header dump before trusting it.

These sit alongside the method-level roadmap in the Critique section (distance-decay kernel, FDR/q-values, cluster-level significance, inverse-variance meta). Together they form a concrete, prioritized to-do list grounded in real use — not speculation.

Adoption into the workflow

Library today, agent-driven tomorrow

Today

Colab for a first look (KBTBD4 template); local conda + YAML for real datasets. Friction: DSSP/MUSCLE install, no single CLI, and long chains of functions whose parameters must be kept consistent by hand.

LLM-assisted (now)

An LLM removes the sharpest edges with zero code change: author/validate the YAML, map arbitrary screen headers onto BE3D's columns, and translate hotspot TSVs into plain-language mechanism — if the tool surfaces confidence so the model doesn't over-read low-pLDDT hits.

A "BE3D MCP"

Expose the modular functions as typed, agent-callable tools returning small JSON summaries + artifact paths, so an agent can drive the brittle multi-step flow end-to-end.

Sketch of the MCP tool surface

fetch_structure(uniprot, isoform?, chain?) → AF/PDB + DSSP fallback + pLDDT summary
run_screen_qc(tsv, cases, controls, col_map) → MWU/KS + go/no-go verdict
build_features(struct, radius|kernel) → neighbors, RSA, pLDDT, SS
compute_lfc3d(features, screens, params) → per-residue LFC/LFC3D + null
call_hotspots(lfc3d, qthr, clustering) → residues + clusters w/ q-values
meta_aggregate(screens[], method) → consensus + I² heterogeneity
characterize(hits, features) → Fisher enrichment, pLDDT/RSA
export_g2p(hits) · export_pymol(hits) → portal TSV / recolor script

Next integrations, in order: PyMOL/ChimeraX recolor export · ESMFold/Boltz for missing structures & complexes · MAGeCK/BEAN upstream (counts→LFC) · cBioPortal/ClinVar overlay · AlphaMissense/ESM cross-check · a lightweight results dashboard.

Methodology. This dossier was produced by an orchestrated agent team ("meta-king → queens → workers"): the BE3D repository was cloned and read at source; four parallel research agents covered the competitive landscape, personas & market, cross-domain critique, and code-level design. BE3D was then installed and actually run — first on its KBTBD4 example, then on four unfamiliar public base-editing screens (KRAS, MCL1, DNMT3A + a LYZ plumbing test) via a hardened, reusable harness, each with an exhaustive parameter sweep and a full decision log. Real usage produced the novel findings above, honest discrimination benchmarks against ground truth, and a live improvement log for the tool. Everything is reproducible and public: github.com/xX-its-amit-Xx/be3d-vetting (dossiers, harness, decision logs, per-target benchmarks, figures, and this dashboard's source).
